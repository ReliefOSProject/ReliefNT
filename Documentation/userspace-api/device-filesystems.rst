============================
设备节点、devtmpfs 与 devpts
============================

devtmpfs
========

``mount("devtmpfs", target, "devtmpfs", flags, data)`` 挂载内核维护的设备节点。
所有挂载共享同一内存文件系统及节点元数据，每个挂载分别维护 ``nodev``、
``nosuid``、``noexec`` 等挂载点策略。普通文件、目录、符号链接及用户创建的
设备节点使用现有 VFS 权限检查。设备打开按 inode 的类型和 ``st_rdev``
分派到驱动，``nodev`` 挂载拒绝打开设备。

设备生命周期
------------

设备注册、注销及分区变化通知 VFS worker 合并更新。首次挂载同步生成完整
设备清单。后续更新保留已有设备的 ``chmod``、``chown``，并尊重用户删除、
替换和占用的名称。设备移除只删除仍由内核持有的原 inode，非空目录保留。
内存不足时保留已发布节点与待重试状态。最后一个公开挂载卸载后，私有 backing
继续保留，后续挂载可看到原有内容及权限。

设备默认归 root，权限为 ``0600``。``null``、``zero``、``full``、``random``、
``urandom``、``tty`` 和 ``ptmx`` 为 ``0666``。``fd``、``stdin``、``stdout``、
``stderr`` 使用指向 ``/proc/self/fd`` 及对应描述符的符号链接。
``pts`` 和 ``shm`` 提供独立文件系统的挂载目录。

devtmpfs 挂载选项
-----------------

挂载数据使用 tmpfs 的 ``mode``、``uid``、``gid``、``size``、``nr_blocks`` 和
``nr_inodes`` 语法。私有 backing 初始为 ``mode=0755,size=0,nr_inodes=0``。
重新配置先验证整个选项集，再原子提交容量和超级块策略。``mode``、``uid``、
``gid`` 只在首次创建 tmpfs 时设置根 inode。已有无限容量的实例拒绝追溯增加
容量上限，已有内容也必须容纳在新上限内，与 Linux shmem 的重新配置约束一致。

devpts
======

``mount("devpts", target, "devpts", flags, data)`` 每次创建独立实例，通常挂在
``/dev/pts``。每个实例有自己的 ``st_dev``、``ptmx`` 和从 0 开始的从端编号；
绑定挂载保留原实例。``statfs`` 报告 ``0x1cd1``，``/proc/filesystems`` 将其列为
``nodev`` 文件系统。打开 ``ptmx`` 后，``TIOCGPTN`` 返回本实例的编号；
``TIOCSPTLCK`` 解锁后才能打开对应从端。

从端报告字符设备号 ``136:<编号>``，但打开时以实际实例和 inode 身份为准，复制
设备号创建的节点不会连接到该终端。``/proc/<pid>/stat`` 中的控制终端设备号也
使用实例内编号；固定虚拟终端仍使用主设备号 4。

devpts 挂载选项
---------------

* ``uid=``、``gid=``：新从端的十进制所有者；未指定时使用创建 PTY 的进程的
  ``fsuid``、``fsgid``。根目录和 ``ptmx`` 归挂载者，根目录初始权限为 ``0755``。
* ``mode=``、``ptmxmode=``：八进制权限，最多保留 ``07777``。默认从端为
  ``0600``、``ptmx`` 为 ``0000``。若直接通过符号链接或绑定挂载打开 ``ptmx``，
  可用 ``ptmxmode=0666`` 或相应的 ``chmod`` 让非特权用户访问。
* ``max=``：实例内保留的 PTY 数量上限，范围为 0 到 1048576。默认不额外限制
  内部 PTY 资源。达到上限时，新建返回 ``ENOSPC``。
* ``newinstance``：兼容选项，可以省略。忽略逗号之间的空字段。

重新挂载从默认值解析选项。成功后立即更新 ``ptmx`` 权限和挂载策略；新选项
只改变以后创建的从端，不重置已有从端的权限或所有者。降低 ``max`` 不会强制
关闭已有会话。未通过验证的选项不会改变现有配置或挂载策略。标记 ``nodev``
的挂载点不能用来直接打开设备。

编号与卸载
----------

最后一个主端关闭时，从端名称被移除，仍打开的从端收到挂断通知。仍有端点引用
的会话继续占用编号和 ``max`` 配额；只剩 ``O_PATH`` 等元数据引用时则可以重用
公开编号。旧的从端 inode 与新会话不同：仍可读取旧 inode 的元数据（链接数为
0），尝试再次打开设备返回 ``EIO``。正常卸载时仍被打开的路径或端点引用会令
挂载忙（``EBUSY``）；释放引用后可以卸载。

打开传统字符设备 ``5:2`` 时，内核从该设备实际所在的目录查找同级
``pts/ptmx``。找到 devpts 后，新会话及主端描述符属于该实例，传统设备本身的
权限决定是否可打开。找不到有效的 devpts 多路复用器时沿用启动阶段的旧 PTY
分配；其他查找错误则返回调用方。

验证范围
========

``tools/test_mount_backend.py`` 覆盖 devtmpfs 共享挂载、元数据、设备号、符号
链接、设备增删、用户替换、挂载策略和内存不足重试，也验证 devpts 实例隔离、
选项、绑定、端点生命周期、编号回收及失败回滚。``tools/test_linux_pty.py``
覆盖 PTY ABI、会话与主端挂断行为。目标系统启动与 udev 集成由 ReliefOS 的
系统迁移验证覆盖。
