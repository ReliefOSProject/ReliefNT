========================================
Intel I225-V and I226-V 2.5GbE Ethernet
========================================

设备范围
========

``drivers/net/i225/`` 提供原生 PCIe 网卡驱动，匹配 Intel I225-V
（PCI ``8086:15f3``）和 Intel I226-V（PCI ``8086:125c``）以太网功能。

配置与功能
==========

``CONFIG_I225_V`` 为 tristate，defconfig 默认内置。选择 ``m`` 时生成
``drivers/net/i225/i225.ko``，并由 ReliefOS 按精确 PCI 别名加载。每个匹配的
PCI 功能拥有独立的 DMA 环和网络接口，并接入现有 ``netdev`` owner 生命周期。

当前实现使用 I225 advanced descriptor 和单个 RX/TX 队列。MSI 可用时由设备中断通知
网络服务，再由任务上下文轮询和复制帧；没有 MSI 服务时退回纯轮询。中断处理只屏蔽
并确认设备中断源，不在 IRQ 上下文执行网络栈操作。链路初始化通过 PHY 管理接口配置
10/100/1000/2500 Mb/s 全双工自动协商；2.5GBASE-T 广告写入 AN MMD 7.32。PHY 初始化
会清除遗留的 loopback、power-down 和 isolate 状态。有效 MAC 优先取自硬件 RAR；只有
RAR 无效时才在固件同步锁内读取只读 NVM shadow，并检查前 64 个字的 16 位累加值为
``0xBABA``；校验失败时拒绝注册接口。驱动不写入 NVM。

发送路径会将不足 60 字节的合法以太网帧用零补齐至 60 字节（不含 FCS），避免
I225 硬件短帧填充的限制，并防止复用 DMA 缓冲区中的旧数据进入填充区域。
启动时显式配置 RX/TX packet buffer，清除主机用附加 RAR 中的遗留地址，保留管理
固件专用条目，并禁用未使用的 IPv6 扩展头解析。只有确认 RX/TX 队列启用后才发布
网络接口；队列状态检查有超时，失败时按既有 DMA 停止流程回收资源。

I226-V 在启动发送队列前会退出固件可能遗留的时间敏感网络（TSN）发送模式，并清除
发送队列的调度配置。驱动保留发送重试缓冲区原有的水位，恢复普通以太网收发。

MSI 模式将 ``EITR0`` 设为 196 个 256 ns 单位，固定节流间隔约 50 微秒。
启动时检查 PCI 电源管理能力链，必要时恢复 D0；能力链损坏或状态切换未生效时拒绝
初始化，避免在低功耗设备上访问 MMIO 或启用 DMA。

PHY 初始化在 SW/FW 同步锁内执行硬件复位，并等待内部复位完成；管理固件禁止 PHY
复位时拒绝接管，不覆盖固件策略。MDIO 完成状态同时检查错误位和返回的寄存器编号。
SWSM 的软件锁与硬件锁分阶段获取，释放时清除两层锁。驱动通过 ``DRV_LOAD`` 标记
与固件交接，并显式关闭 EEE 广告及低功耗空闲，保证启动策略不依赖先前系统的配置。

驱动记录自身取得的 ``SW_FW_SYNC`` 软件资源位。若 SWSM 竞争导致资源无法释放，
保留 MMIO 映射与 ``DRV_LOAD``，并在后续 STOP 时重试；释放只清除自身持有的位，
保留固件及其他软件的资源位。

支持标准 1500 字节 MTU。软件收发接口的帧长度不含 FCS，最大为 1514 字节；加上
FCS 后的线上帧最大为 1518 字节。当前不支持 VLAN、巨帧、硬件校验和或分段卸载、
多队列、RSS、时间戳、EEE 配置及运行期间的 PHY 重配置。数据收发始终由现有网络
服务在任务上下文处理。

验证范围
========

``tools/test_i225.py`` 使用 ASan/UBSan 编译真实驱动对象。两款网卡均以 PCI/MMIO/DMA
边界模型验证设备匹配、64 位 BAR 和 DMA 地址、NVM/PHY 管理、描述符环回绕、错误帧、
分配失败、无网线启动、注册失败及卸载回收。I226-V 用例还验证发送队列启用前已恢复普通发送模式。

错误路径测试覆盖 NVM 校验和不符、NVM/MDIO 超时或错误后的固件锁释放，以及 DMA
停止失败时保留全部 DMA 资源并在重试卸载成功后释放。

NVM 和 PHY 同步资源分别覆盖释放失败、重复 STOP 仍失败，以及竞争消失后 STOP
成功的路径，验证映射与驱动所有权标记在资源释放前保留。

模型还覆盖 PCI 电源管理能力链和 D0 恢复、PHY 复位被固件禁止或未能完成、SWSM
读取获取软件锁的语义、MDIO 返回寄存器编号不符、队列启用超时及短帧清零补齐。

中断模型覆盖 MSI 通知、没有 MSI 时的轮询回退、ICR 读取清除、IMS 写 1 置位和 IMC
写 1 清除语义，以及重新启用中断时到包或链路状态变化（LSC）的竞态。卸载测试还覆盖
停止通知接入后到达的迟到 IRQ，验证它不会再次通知网络服务。

两款网卡的物理链路协商、长时间收发和实际吞吐仍需在实体硬件上验证。PCIe ASPM
L1.2 当前由平台固件配置。启用 L1.2 的 I226 平台在高流量下可能丢包，详见
`Linux igc 的 L1.2 修正 <https://github.com/torvalds/linux/commit/0325143b59c6>`__。
